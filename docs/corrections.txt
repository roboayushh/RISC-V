Corrections following the 25 November 2026 audit

The audit in audit/2026-11-25/REPORT.txt describes baseline 75b9c77, before
these changes. It is retained as historical evidence, not the current status.

Resolved

1. Instruction-memory capacity and loaded image length are explicit. INIT_WORDS
   gives the number of file words. The ROM reads that range and returns NOP
   beyond it in both RTL and synthesis. Empty images initialize to NOP. Wrappers
   expose IMEM_WORDS (defaults to IMEM_DEPTH). With a partially occupied ROM,
   callers must set the actual image length. For example, the 22-word mixed
   image in a 64-word ROM uses IMEM_DEPTH=64 and IMEM_WORDS=22.
2. Integration and memory benches call $fatal(1) on unsuccessful summaries.
   Their standalone runners require a completion marker and propagate simulator
   and pipeline failures. A zero-exit simulator without PASS output is rejected.
3. Integration timeout is fatal. Completion is sampled after nonblocking updates.
4. rv32i_core and rv32i_top now default to integration.hex, depth 22. The terminal
   branch is at 0x54, RAM word 16 and x4 contain 6, and halted is asserted.
   The compatibility core retains its legacy 11-word workload with exact depth.
5. The comparison labels timing estimates, removes the measured-result claim,
   and compares throughput using CPI and clock period. Device Fmax predictions
   unsupported by a target implementation were removed from the timing notes.
6. The branch runner passes literal program names and filenames, avoiding
   conditional-string parameter evaluation differences for compatibility with the Icarus 12 simulator supplied by Ubuntu.
7. The missing video anchor now points to the integration guide. A GitHub Actions
   workflow runs regression, assembly-image checks, module checks, synthesis,
   and behavioral acceptance on pushes and pull requests.

Current evidence

- Eleven original regression suites pass.
- Six assembly sources rebuild to their committed hex images.
- Sixteen RTL modules pass lint, synthesis, latch, and structural checks.
- scripts/check_acceptance.py checks both RTL and synthesized ROMs over partial
  and empty images, misaligned and invalid addresses, default demo completion,
  80 samples of the core RTL/netlist trace, rejection of wrong SUB, rejection of
  a disabled completion flag, and rejection of missing simulator PASS output.
- synthesize.sh includes these behavioral acceptance checks after generating
  the netlist. Synthesis must not be signed off on structural checks alone.
- The regenerated Yosys 0.71 generic mapping has 22,531 cells, 9,545 muxes and
  9,248 flip-flops. ALU and branch-target depths are 69 and 57 generic levels.
  The exact tool version and breakdown are in synthesis_report.txt.

Submission snapshots

and dated audit evidence remain historical snapshots. They contain the original

Remaining requirement

Measured maximum operating frequency and physical FPGA implementation remain
unverified. The selected target is now xc7a35tcpg236-1 using Vivado, consistent with the
existing example in docs/synthesis.md. However, Vivado, nextpnr and OpenSTA are unavailable locally.
The 70-140 MHz calculation is an illustrative assumption-based range, not a
substitute for target-specific static timing. CPI=1 is a verified architectural
property, not proof of the maximum clock rate. The prepared timing flow is scripts/run_vivado_timing.sh. It has not been
executed in Vivado here. A live demonstration also needs
to be performed by the team; source files and passing simulations do not certify
that it has occurred.
